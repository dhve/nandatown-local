# Path Convergence Plan (Phase 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Converge the build with "NANDA Town: Test the Path, Not Just the Protocol": honest five-status result semantics with town-fault attribution, first-broken-stage reports with rerun commands, the bring-an-existing-agent path test against a live external A2A endpoint through an exact versioned profile, sanitized signed receipts separate from private artifacts, and the Town Proof badge.

## Tasks

### Task 36: Honest result semantics
StageStatus gains `error` (Town, its driver, or its evaluator malfunctioned; never the subject's fault); EvidenceResult verdict gains `error`; the report labels not_enough_evidence as Inconclusive and error as ERROR (town fault). After the first failed stage, unreached later stages report not_tested with a "not reached" note instead of inconclusive. Every report prints `First broken stage:` (with its note) when anything broke and a `Rerun:` command carried in run.config. Missing evidence never becomes a pass; an error verdict outranks failed in reporting honesty.

### Task 37: Path A, bring an existing agent
`path_profiles.py`: frozen, fingerprinted, versioned profiles starting with `a2a-capability-fulfillment@0.1` (synthetic two-widget order with a run nonce, expected exactly one terminal fulfillment containing the nonce, controlled condition duplicate_request, limits). `path_runner.py`: resolve the subject (direct URL, or a pinned local index file with resolution hops recorded), then stage by stage: agent_card_retrieval, descriptor_consistency (optional pinned digest; mismatch names expected and observed digests), protocol_invocation (native A2A message/send through the deterministic Town requester), semantic_result (exactly one fulfillment, correct total, nonce echoed), duplicate_request (the same logical order again; the observable invariant is no second distinct fulfillment). Failures cascade: later stages not_tested. Town-side exceptions become ERROR, not subject failure. Output: the same evidence bundle (mode "path") with subject locator, descriptor digest, resolution hops, rerun command, report, attestation. CLI: `nandatown test-agent --url URL [--profile a2a-capability-fulfillment@0.1] [--pin-card-digest sha256:..] [--index FILE --agent-name NAME]`, alongside the existing join-based --cmd/--wait modes. `a2a serve --defect wrong_total|duplicate_fulfillment|card_drift` plants defects in the reference agent for the proposal's five starter cases. Tests cover healthy, planted wrong result, duplicate fulfillment, card mismatch with both digests named, unreachable endpoint (resolution fails, later stages not tested), and a forced town-driver fault reporting ERROR.

### Task 38: Receipts and Town Proof
`receipt.py`: a shareable receipt is a deliberately sanitized signed derivative: the exact claim (capability, subject release basis, profile, verdict), observer id, time window, coverage (which stages were tested), limitations, and evidence digests; full bodies and traces stay in the bundle. `nandatown receipt <bundle>` writes and signs it; `nandatown verify-receipt <file> [--bundle dir]` verifies offline (signature, signer id derivation, digest cross-check when the bundle is present). `nandatown proof <bundle> [--freshness-days N]` renders the TOWN-TESTED badge sentence only when the verdict passed, the receipt verifies, coverage is full, and the window is fresh; otherwise it says exactly why not. The signature proves a named key committed to those bytes, not that the agent is safe; the badge is narrow and expiring by construction.

### Task 39: Converge the docs and ship
docs/convergence.md maps the proposal's component table (CLI, profile loader, orchestrator, resolvers, protocol drivers, evaluator, evidence writer, reporters) to the shipped modules and records the proposal's boundaries verbatim in spirit: listed is not installed, a card is a declaration while a Town result is an observation, liveness does not prove fulfillment, a favorable result grants no permissions, a badge is policy over evidence. README gains the path-test section and the receipt/proof flow. Full suite, dash check, push, CI green, memory.
