# Full Town Implementation Plan (Phase 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow the Alpha 0.2 monolith into the full local NANDA Town from the Everything doc: twelve swappable protocol layers, the deterministic Lab simulator with YAML scenarios and validators, the real-agent Track (existing), campaigns, a SkillMD registry, an HTML visualizer with replay, the five shared JSON schemas, and one CLI that covers everything, published to github.com/dhve/nandatown-local.

**Architecture:** The Lab is a seeded discrete event engine. Agents are role state machines that touch the world only through a TownAPI facade, and the facade routes every call through the twelve layer plugins, each of which emits attributed TownEvents. Scenario YAML picks the plugin for each layer, the agents, the faults, and the validator. Lab and Track runs both end in the same evidence bundle, so report, verify, replay, visualize, and campaign work identically for both.

**Tech Stack:** Adds pyyaml. Everything else unchanged.

## Global Constraints

- Same seed and scenario always produce the same trace (event list identical after normalizing run_id). No wall clock, no unseeded randomness inside the engine.
- Every state change in any layer is a TownEvent with a named observer. Validators judge from events alone, so verify can replay them.
- Faults are declared in the scenario, exactly as merged: drop, duplicate, or delay the nth message of a kind.
- The privacy layer redacts declared fields from exported events; redacted values must never appear in events.jsonl.
- One CLI. No em or en dashes in shipped files. No Claude attribution in commits.

## Tasks

### Task 10: Layer framework and the twelve defaults
`src/nandatown/layers/` with `__init__.py` (LAYER_NAMES, register/resolve registry), one module per layer, each with a v1 default plugin: transport `memory.v1` (latency, drop/duplicate/delay faults), communication `envelope.v1` (conversation ids, correlation), identity `keys.v1` (per-agent secret, agent card), registry `index.v1` (publish cards, capability lookup, verification flag), auth `hmac.v1` (sign/verify envelopes and cards), trust `reputation.v1` (receipt-driven score), payments `ledger.v1` (balances, escrow hold/release/refund, transfer events, conservation), coordination `contractnet.v1` (announce/bid/award), negotiation `haggle.v1` (offer/counter/accept with min/max bounds), memory `kv.v1`, privacy `redact.v1` (field redaction on export), data_facts `evidence.v1` (signed one-observer one-subject one-time records). Tests in `tests/test_layers.py` cover registry resolution, ledger conservation and escrow, hmac verify rejecting a forged sender, redaction, and reputation updates.

### Task 11: Sim engine, TownAPI, scenario loader
`src/nandatown/sim/engine.py` (heap queue of (at, seq, fn), seeded rng, emit(), layer wiring), `sim/scenario.py` (ScenarioSpec pydantic + YAML loader + bundled scenario listing), `sim/api.py` (TownAPI: send, reply, register, lookup, pay, escrow, remember, recall, attest, reputation, announce, bid, award, offer, counter, accept). Tests: deterministic double-run equality, fault drop actually drops the nth matching message, unknown plugin fails loudly.

### Task 12: Role agents and the six scenarios
`sim/agents.py` state machines: seller, buyer, auctioneer, bidder, double_bidder, voter, double_voter, ballot_box, proposer, acceptor, manufacturer, supplier, customer, spoofer. `sim/scenarios/*.yaml`: marketplace (negotiation, payments, trust, memory, privacy, two rounds), auction (sealed signed bids, exactly one charge, refunds), voting (signed ballots, dedup, double-vote rejected), consensus (quorum commit under drops with retries), supply_chain (contract-net, milestone escrow, assembly, delivery), capability_spoofing (forged card unverified, honest seller wins all business). Tests run each scenario end to end and assert its key events.

### Task 13: Scenario validators and lab runner
`sim/validators.py`: per-scenario checks producing StageResults from events alone plus a shared ledger-conservation and privacy-leak check; `sim/runner.py` run_lab(name, out_dir, seed) writing the same bundle shape with manifest mode "lab". Generalize `bundle.py` verify to dispatch replay by mode. Tests: every scenario verdict passed, verify clean, tampering caught, seed change changes the trace.

### Task 14: Unified CLI, campaigns, skills, replay, visualizer, schemas
`campaign.py` (precommitted plan, N trials, per-stage distribution, aggregate.json + report), `skills/` (SkillMD frontmatter parse/validate/list + builtin skills for the reference roles), `replay.py` (step-through printout), `visualizer.py` (self-contained HTML: agents on a town map, messages animating along the timeline, event log, stage results), `schemas.py` (export run plan, agent message, town event, release reference, evidence record JSON Schemas; commit them under `schemas/`). CLI: run (lab or track by name), scenarios, profiles, layers, skills, campaign, report, verify, replay, visualize, coordinator, schemas. Tests for campaign aggregation, skill validation, visualizer HTML content, schema export.

### Task 15: Docs, CI, ship
README overhaul covering Lab, Track, layers, scenarios, campaigns, skills, visualizer, BYOA contract; `docs/architecture.md`; `.github/workflows/ci.yml` (pytest, 3.11 and 3.12); push everything to dhve/nandatown-local.
